# Local identity-exposure policy

`runtime/identity_guard.py` adds a fail-closed prerequisite for explicitly authorized lab submissions. `inspect()` returns a redacted report; `require_private_context(job)` writes `identity-state.json` and raises before submission if any check is blocked or unknown. Runtime integration must check immediately before intent and again before submission. This file does not authorize device access or qualify radio behavior.

The collector runs one fixed, read-only script using `/usr/sbin/chroot /proc/1/root /system/bin/sh`. It verifies Android SDK/fingerprint property availability and the Android init network namespace. It reads airplane/mobile-data/Bluetooth settings, the current `wlan0` address, interface/address listings, **all** IPv4/IPv6 route tables, and filter firewall rules. There is no Internet request, public-IP lookup, IMEI/SIM read or identifier spoofing. The inspector does not mutate settings. Unsupported required observations, permission denial, incomplete output, unexpected syntax, timeout or output overflow produce unknown checks and block. Unavailable firewall inspection never grants an egress-lock exception.

Passing requires all of these observations:

- Airplane mode is `1`; mobile data and Bluetooth are `0`.
- `wlan0` has a syntactically valid locally administered unicast MAC; the Android placeholder `02:00:00:00:00:00` is rejected.
- No interface has an assigned address outside explicitly permitted private, link-local or loopback ranges, unless both IP-family egress locks below are independently verified.
- No table has a default route or an egress route outside those ranges, unless both IP-family egress locks are independently verified. Broad VPN split defaults and public host routes otherwise block too. Understood non-forwarding routes may pass; unknown route syntax always blocks. The limited-broadcast route and IPv6 multicast routes have explicit narrow exceptions.
- No recognized cellular interface has its `UP` flag set, and `wlan0` exists. Down cellular interfaces may exist.

The collector has a three-second observation deadline and accepts at most 1 MiB of output. It creates a dedicated process group and kills that group on timeout, overflow, handled cancellation or collector failure, with a bounded 250 ms reap. Raw output stays in memory. Public JSON contains only schema version, inspection timestamp, aggregate allowance and fixed check IDs/status/reason codes. It never includes addresses, MAC values, Android fingerprints or exception text.

## Prepare and restore normal connectivity

`runtime/privacy_profile.py` exposes `prepare(job)`, `restore(job)` and `status(job)`. Preparation saves the four original Boolean settings to root-owned mode-0600 `/data/local/tmp/hijacker-qca/bender-privacy/pending.json` on the Android host before any privacy mutation. The directory is mode 0700. The atomic journal write and its directory are fsynced; a host-wide nonblocking lock serializes operations. An existing journal is never overwritten. Invalid, oversized, nonregular or improperly owned journals block recovery rather than supplying settings to commands.

Preparation requires both `/system/bin/iptables` and `/system/bin/ip6tables`. It refuses a pre-existing `BWL_PRIVATE` name. For each family it creates only that owned filter chain, containing loopback RETURN followed by DROP, and inserts its jumps at position one in OUTPUT and FORWARD. No unrelated chain is flushed or edited. Exact rules, their order and unique first-position hooks are verified from privileged listings. It then enables airplane mode, disables mobile data and Bluetooth, and enables Wi-Fi, verifying actual Boolean settings afterward. No MAC changes or saved-network rewrites occur; if the current MAC still blocks, Android's Wi-Fi privacy settings require attention. An active profile can therefore coexist with a blocked identity check.

When both filter locks are verified directly by the inspector, configured public addresses/default routes can pass with fixed reason `configured_but_egress_blocked`. This avoids deleting Android-managed routes. Missing/malformed address or routing evidence, unsafe MACs and other failed checks still block. A caller-supplied request or a journal saying “active” never establishes the exception. The lock covers ordinary kernel IPv4/IPv6 OUTPUT and FORWARD traffic; it does not establish suppression of Wi-Fi management frames, layer-2 packet injection, modem emissions, firmware offloads or compromised-root behavior.

Preparation success intentionally leaves `pending=true` until **Restore normal connectivity** succeeds. Restoration reapplies saved settings while locks remain, verifies them, removes only recognized owned rules/chains, checks actual settings and absence of owned references, then deletes/fsyncs the journal. Failure or handled cancellation during prepare attempts a bounded rollback; incomplete rollback keeps the journal and a pending report. Force termination/reboot can leave a pending obligation; status/recovery uses the durable host journal rather than a job directory. Changes made externally during the profile can be overwritten by restoration; network associations and transient sessions are not reconstructed. Unknown changes within owned chains are preserved and block automatic cleanup. With no journal and no owned rules, status/restore reports `idle` and makes no restoration claim.

Each host command is bounded to three seconds and 1 MiB; a transaction has a 30-second command budget, with a separate 30-second rollback budget after preparation failure. Reports in `privacy-state.json` contain only fixed text, timestamps and Boolean state (`pending`, `active`, `restored`), never the saved settings or identifiers. Root and compatible Android commands are prerequisites. Physical handset behavior remains unqualified.

The fixed commands follow primary AOSP implementations: [connectivity airplane-mode shell command](https://android.googlesource.com/platform/packages/modules/Connectivity/+/0eccf35b6b1b123996ee41e4cc078cf79c35be89/service/src/com/android/server/ConnectivityService.java), [data/Wi-Fi svc translations](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/cmds/svc/svc.sh), and [Bluetooth enable/disable shell commands](https://android.googlesource.com/platform/packages/modules/Bluetooth/+/0f98ddca48c98e78ba2720ab25c43d02c87a5027/service/java/com/android/server/bluetooth/BluetoothShellCommand.java). These references establish command syntax, not handset qualification.

These checks are a conservative local policy, **not an anonymity guarantee**. A local MAC bit does not establish freshness, randomness, unlinkability or the source address of every transmitted frame. A private IP can still identify a local participant. Route observations do not establish an externally observed IP; no external endpoint is queried. Settings and recognized interface names do not measure RF emissions or prove modem shutdown. Kernel/root compromise, an unrecognized future modem interface, firmware behavior and state changes after inspection remain outside this proof. Checks can block otherwise safe configurations when their evidence cannot be interpreted. Do not label a pass “anonymous,” “IMEI hidden” or “untraceable.”

Android documents that Wi-Fi MAC addresses can be observed and that randomized MACs set the local/unicast bits; persistent randomization can still retain an address for a network. This supports the bounded MAC check, not a freshness claim: [AOSP MAC randomization behavior](https://source.android.com/docs/core/connect/wifi-mac-randomization-behavior). Android separately describes network transports/capabilities in [NetworkCapabilities](https://developer.android.com/reference/android/net/NetworkCapabilities) and telephony identifiers in [TelephonyManager](https://developer.android.com/reference/android/telephony/TelephonyManager); this implementation does not call identifier APIs or claim that a Wi-Fi-layer gate controls telephony identity.

Offline validation: `test_identity_guard.py` has 24 tests; `test_privacy_profile.py` has 20. Synthetic cases cover policy-table defaults, IPv6, split VPN routes, assigned public addresses, cellular links, missing/malformed evidence, lock exceptions, redaction and bounded process-group termination/cancellation. Simulated transactions cover every apply-command failure, rollback, incomplete rollback, cancellation, partial-chain restart recovery, exact hook order, collisions, invalid journals, actual-setting mismatch, unchanged pending obligations and preservation of unrelated rules. No phone access was used. Handset utility compatibility and actual submission-time behavior remain unqualified.
