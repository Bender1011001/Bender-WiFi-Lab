# OnePlus internal Wi-Fi: prior art and the next research contribution

Review date: November 14, 2026, America/Los_Angeles. This is a source and retained-evidence review. No new radio experiment was performed. An attempted read-only handset refresh failed because the selected ADB device was unavailable.

**The strongest next candidate is a single-phone tester for the boundaries between two simultaneous Wi-Fi connections.** It would first measure network isolation, then examine whether connection-specific traffic and security state remain separated during ordinary connection changes. This is a plausible tool contribution and a route into vulnerability research; neither a working implementation nor a new vulnerability has been established.

The phone's saved Android diagnostics provide a concrete feasibility lead: STA+STA support, multi-internet mode 2, and enabled multi-internet concurrency. The same report disallows same-band and same-BSSID pairs and disables local-only concurrency. These are reported settings, not proof that two useful associations can be established. Dual STA also differs from Wi-Fi 7 MLO. The extracted values, source line numbers and input hash are in `dual-sta-capability-evidence.json`; the failed refresh is separately recorded in `dual-sta-current-evidence.json`.

The comparison below distinguishes our measured results, upstream authors' reports, and code that has only been inspected.

The local source for our three-target evidence is `hijacker-qca/docs/ROUTER-CORROBORATED-TESTS.md`, with sanitized records in `hijacker-qca/evidence/router-corroborated-20261113.json`. The Roku disconnected from 2.4 GHz and subsequently reconnected on 5 GHz; this is not evidence of a transmission affecting a client already connected on another band. Our separate PMF counter experiment observed zero increments without proving receipt or rejection at the phone, so it supplies no PMF vulnerability claim.

One important source correction: the March hidden-STA description must not be applied to every Loukious branch. In the retained July diff, `create.type = WMI_VDEV_TYPE_AP` appears at line 1614; raw encapsulation and peer creation follow, and the direct path calls `cdp_tx_send_exc` around line 1882. Those are lines in the saved aggregate diff, not upstream file line numbers. We have not built or run that patch.

**The research opportunity is narrower than “dual Wi-Fi is new.”** Android already supports concurrent station connections. Cisco documented two identities, accounting issues and incomplete quarantine of dual-connected phones in 2023. AirSnitch already studies isolation failures across encryption, routing and switching. A new tool should credit and reproduce suitable baseline cases, not relabel them as discoveries. [Android implementation](https://source.android.com/docs/core/connect/wifi-sta-sta-concurrency), [Cisco study](https://www.cisco.com/c/en/us/td/docs/wireless/technology/dual-wi-fi/b-impact-of-dual-wi-fi-acceleration-on-enterprise-networks.html), [AirSnitch](https://www.airsnitchattacks.com/).

| Candidate, in recommended order | Distinct contribution to attempt | What would make it credible; current blocker |
|---|---|---|
| 1. One phone as two measured Wi-Fi endpoints | A repeatable isolation test that binds each endpoint to a verified connection, proves the external packet path, and separates AP forwarding from gateway routing and Android-local delivery. | Demonstrate two actual associations and correct positive/negative controls. Establish that a packet really traversed the network. Support flags alone are insufficient. No equivalent complete phone workflow was found in this bounded review; global novelty is unproven. |
| 2. Security-state separation between concurrent connections | Compare each connection alone with both active, then change one controlled connection and check the other for unexpected traffic, filtering, offload or negotiated-security changes. | A reproducible cross-connection effect with a root cause and a real security boundary. Ordinary shared-radio contention, default-route changes, allowed socket failover, global counters and the known two-MAC quarantine issue do not qualify. No such anomaly has been observed here. |
| 3. Full packet evidence while remaining connected | A phone-side recorder that correlates actual management frames, connection state and per-interface events without leaving the association. | Prove the receive path and its coverage. Our beacon event stream lacks full IEs, managed frame registrations failed, and monitor-status query 225 returned EPERM. Related local-packet-capture code already exists; exposing it alone is not a new concept. |
| 4. Wi-Fi 7/MLO security consistency | Extend a qualified measurement engine to multiple links and compare negotiated state and behavior across them. | A compatible AP, correct link identities and a fresh dedicated prior-art review. Current dual-STA support does not establish MLO support in the test setup. |

Candidates 1 and 2 form a useful sequence. The first can deliver a practical tool even if no vulnerability exists. The second is the higher-impact research question, but a successful negative result is also meaningful. The most compelling demonstration would show a clearly stated policy, the actual packet path, the observed result, and a control that changes that result for the expected reason.

The owned Rockspace network makes a second physical AP available in principle. Its model, supported bands, operating mode and upstream topology remain unknown. It may route, bridge, or extend the existing LAN. Therefore it cannot yet be treated as an independent trust boundary or a Wi-Fi 7 AP. There is no need to retrieve the model to complete this comparison; it becomes relevant before the live feasibility run. The existing WNC guest/primary setup is also potentially useful if a supported different-band pair and the intended policy can be verified without changing household service.

The next run is specified in `FIRST-EXPERIMENT.md`. It starts with ordinary connections and uniquely tagged test traffic. It does not require deauthentication or rely on the unqualified PMF counters.

This review covered the named Qualcomm projects, selected implementation commits/branches, Android concurrency documentation, Cisco's dual-Wi-Fi study and AirSnitch.
