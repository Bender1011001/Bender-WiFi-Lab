# First experiment: qualify two independent Wi-Fi connections

Status: designed, not executed. Research question: can this OnePlus 13 provide two separately observable Wi-Fi endpoints, with a demonstrable external packet path, using its internal chipset and installed software?

This test qualifies an instrument. Passing it establishes no vulnerability and does not establish that the full Bender app has this feature.

Use only the two owned, explicitly selected networks. Record their intended topology and policy before interpreting traffic. Rockspace model and router/extender/AP mode are still unknown. Determine its supported bands and whether its LAN is bridged into the WNC network; ownership and a separate box do not settle either question. Keep credentials and raw identifiers in private evidence.

Android's documented multi-internet request selects a band and lets the framework choose a saved network; it does not accept an exact SSID/BSSID selection for that path. Validate the resulting identity through each network callback before any test traffic. Request construction, observed connection and test authorization are separate states. See the [Android concurrency implementation](https://source.android.com/docs/core/connect/wifi-sta-sta-concurrency).

| Gate | Procedure and fixed limit | Required evidence / stopping point |
|---|---|---|
| 0. Record starting state | Read device/build/driver identity, active connections, routes, requested-network ownership and per-interface identifiers. Record whether a VPN, proxy, tethering or application forwarding changes the path. | A usable current handset connection and a known restoration target. The previous read-only attempt found no ADB handset; do not reuse that failed attempt as current evidence. |
| 1. Demonstrate two associations | Request one supported different-band pair once, using the framework path. Allow at most 60 seconds; observe both for 30 seconds. | Two concurrent network objects and corresponding interfaces, different client identities/BSSIDs, actual bands, and association evidence from both APs where available. A support flag or two IP addresses alone does not pass. Stop if the selected network differs from either authorized identity or either association disappears. |
| 2. Prove each outbound path | Bind a test socket separately to each network. Send five non-sensitive tagged packets per leg to a controlled listener, at most one per second. | Listener-side records correlated with the nonce, sequence and selected interface; record routes and source addresses. The listener must be reached through the intended Wi-Fi path. Binding a socket is not itself path evidence. No public reflection or internet discovery service is needed. |
| 3. Prove a path between the endpoints | Only after feasibility is established, send at most five tagged packets per direction on a known allowed path, with a receive record tied to the intended interface. | Independent AP/wired/over-air evidence of the forwarding path, with outgoing packet copies and Android local delivery excluded. A capture on the phone alone is insufficient during calibration. If no observer can distinguish the path, label this gate unresolved. |
| 4. Exercise controls | Repeat the same bounded path with the intended block in place, then with one test endpoint deliberately released. Restore the original allowed configuration and repeat its positive control. | Allowed traffic succeeds; the specified block prevents the expected path; the absent endpoint cannot receive. Each network-policy change needs a recorded before/after value and restoration check. A failed positive control invalidates the blocked result. |
| 5. Repeat and restore | If the controls pass, repeat the completed sequence once. Release only the request owned by this experiment and restore its original state. | Repeatable results, both router and phone recovery observations, and final reachability. Do not remove another consumer's connection or replay an interrupted transmission. |

If same-host IP routing shortcuts gate 3, evaluate a receive/transmit path tied to actual interfaces or genuinely separate network contexts before continuing. Raw Ethernet access and network namespaces are possible engineering approaches, not capabilities established on this handset. Even an interface-bound packet can be reflected or copied locally; validate it with the independent observer. If this cannot be resolved, narrow the tool to two separately observed outbound paths rather than claiming it measures client isolation.

Distinguish guest-to-main policy, client-to-client isolation on one BSS, communication across BSSIDs, and routing between separate routers. They are different tests. The phone's reported prohibition on same-band/same-BSSID concurrent connections may exclude a same-BSS test entirely. Unsupported topology remains an explicit limitation.

For every observation retain a run identifier, monotonic time and clock source, network/interface identity, selected band, packet nonce and sequence, direction, evidence source, expected policy, and observed outcome. Synchronize or bracket external clocks before making timing claims. Record packet and event loss. Public exports should replace network identifiers with stable experiment aliases; keep raw evidence private.

Any failed prerequisite stops the dependent gates. There are no automatic reconnect or transmission retries. The total payload traffic is bounded by the gates above; packet timeouts are measured outcomes, not triggers to flood or escalate.

Once this instrument works, the next research question is whether ordinary changes to connection B alter connection A's security-specific state. Compare A alone, A+B, B reconnecting, and A after B is removed, with the same bounded traffic and an independent observer. Separate expected resource sharing and Android routing behavior from a policy violation. Attribute any PMF or replay counter to an interface before using it. A candidate finding requires repeated results, a precise affected build, a causal explanation and a meaningful attacker/defender boundary; a graph changing is not enough.
